# Rebuilt scene runtime audit

Audit date: 2026-10-02. Scope: the seven `.scene.js` worlds and `scene-host.js`, `scene-surfaces.js`, and `scene-gallery.js`. Fair, Royal, Control, generated archive content, preserved sites, and the shared countdown API were excluded from implementation changes.

## Shared corrections

- Crossing the 700px phone boundary reconstructs the concept with its authored viewport model. The native archive, real deadline, press tally, pending request and normalized archive position survive. No page reload or reset request is involved. Rebuilding waits for an open preview to close; viewport changes during loading are coalesced. Loading retains the complete native archive.
- Pointer releases now belong to the initiating pointer. A second simultaneous pointer cancels the gesture; vertical touch panning, drag release, lost capture, cancellation, blur, hiding, Escape and graphics loss cannot complete an abandoned press. A dragged native hover anchor suppresses its subsequent click.
- A new action/focus/scroll cancels an unfinished preview approach. Only the active preview's real native anchor may open its preserved page. Camera approaches complete immediately when reduced motion is enabled. Modal close suppresses the restoring focus reframe; resized scroll runways restore the original normalized position.
- Local/remote decorative response ages advance only in visible, unfrozen scene frames. Actual clock values still come from the shared state. Reduced motion settles the number reels immediately; failed and rate-limited presses do not dispatch a successful ceremony.
- Disposal now reaches child lights/shadow targets, skeletons, original GLB materials replaced by ink, detached resources, scene environment textures and reflection targets. Shared image bitmaps close once. Already disposed focus-outline geometry is removed from the owned set. Intentional teardown releases its graphics context. Late model/image results cannot promote a disposed scene, including navigation away during loading.
- Native hover links retain the original `href`, `target` and `rel`; click, middle-click and context-menu picking rechecks the nearest visible solid. Initial theme/show hash links travel to their physical station. Preview images remain actual decoded archive stills and do not receive scene tone mapping.

## Focused render/profile follow-up

The optional synchronous `controller.render(dt)` hook is used for both the initial composed frame and subsequent paints, so Road's SSAO does not silently fall back to a different first-frame pipeline. A whole-host fault harness now injects a failing first/later render hook together with throwing artist cancellation, controller disposal and owned-resource disposal. Native clipping/classes, original status/secret parents, fallback crown, canvas/runway, fonts, listeners and renderer/context resources are restored/released despite those cleanup errors.

Each host's `mobile` getter is now bound to its authored profile. A loading viewport can cross and return across separate asset/camera awaits without selecting different profiles. The central wrapper still rebuilds on a real breakpoint crossing and defers it while the preview is open. Tested desktop→phone→desktop rebuilding preserves the real getter state, pending reset and normalized archive position, with exactly one canvas and one registered owned font. A pagehide while a controller is loading never promotes its late completion.

Timeline duplication after a rebuild came from comparing a relative template URL with the absolute theme-qualified native URL. Destination identities now resolve both URLs and ignore only the theme parameter; excess previously generated timeline duplicates are removed. The whole-host rebuild fixture retains one canonical native timeline through both profile transitions.

Evidence fixture: [host-lifecycle.mjs](validation/host-lifecycle.mjs). It executes the complete saved host with injected dependency imports and a mock DOM/renderer, using real Three scene/camera/resource objects. It proves failure/state/ownership behavior, not GPU shader compilation, actual DOM rendering, device performance or browser pointer/link defaults. The prior shared resource/reel/input harness and current ES-module parse also pass.
